# ARIA 智能报价辅助系统 — 用户操作手册

**版本：** v1.2  
**日期：** 2026-06-20  
**适用对象：** 报价工程师、知识库管理员  
**RAG 设计：** [supplementary/rag-design.md](supplementary/rag-design.md)

---

## 1. 系统简介

ARIA 是本地部署的 AI 报价辅助工具，覆盖 EDAG 报价流程的 **四大输出**：

| 输出 | 系统页面 |
|------|---------|
| 历史技术对标 | RFQ 分析 |
| 技术方案草案 | 技术方案 |
| 待澄清技术问题 | 澄清问题 |
| 人力报价预测 | 人力报价 |

**重要：** AI 输出仅为参考草稿，导出前请务必人工审阅确认。

**Demo 说明：** RFQ 解析、历史对标、Excel 生成为 **真实 AI 能力**。「技术方案」「澄清问题」及人天构成明细在 Demo 阶段为 **预览界面（Mock 数据）**；详见 [demo-scope-brief.md](demo-scope-brief.md)。界面中标有 **「Demo 预览」**。

## 2. 访问系统

- **内网地址：** http://aria.company.internal（或部署方提供的地址，如 http://localhost）
- **远程访问：** 先连接公司 VPN，再访问上述地址
- **浏览器：** 推荐 Chrome / Edge 最新版

## 3. 五步工作流程

```
① RFQ 分析 → ② 历史对标（同页） → ③ 技术方案 → ④ 澄清问题 → ⑤ 人力报价
                                                      ↑ 知识库（管理员后台）
```

每个业务页面顶部有 **当前任务** 栏与 **五步进度条**。请先上传 RFQ 并完成解析，再依次审阅各步 AI 草稿。

### 3.1 ① RFQ 分析

1. 进入左侧 **「RFQ 分析」**
2. 在 **「最近分析」** 中选择历史任务，或上传新的 `.docx` RFQ
3. 等待 AI 解析（约 1–5 分钟，页面显示进度）
4. 查看 **Function 模块**、交付物、里程碑
5. 查看 **技术维度对比表**（3–5 个相似历史项目）及置信度
6. 点击相似项目行可 **展开** 查看 RAG 命中片段与来源文档
7. 若某 Function **无历史参考**，对比矩阵下方会显示警告，请重点人工补充
8. 编辑对比表 → **保存修订** → 勾选确认
9. 点击 **「下一步：技术方案」** 或左侧导航继续

**置信度：** 🟢 高 / 🟡 中 / 🔴 低（低置信度须重点人工核对）

### 3.2 ③ 技术方案（Demo 预览）

1. 进入 **「技术方案」**（须已选定 RFQ 任务）
2. 点击 **「生成方案草案」**
3. 按 Function 查看匹配的 **历史技术模块卡片**（假设/输入/工作内容/交付物）
4. 每卡片显示来源项目、相似度、偏差率（Demo 为示例数据）
5. 可在文本区做初步编辑
6. 继续 **「澄清问题」**

### 3.3 ④ 澄清问题（Demo 预览）

1. 进入 **「澄清问题」**
2. 点击 **「加载 Mock 示例清单」** 预览表格结构
3. 查看表格：序号、待澄清问题、涉及功能、影响程度、历史依据
4. 可编辑、删除条目
5. 点击 **「下载 Q_A Excel」** 导出（需求文档 5 列结构；客户正式 Q_A 模板确认前列名可能不同，见 [qa-field-confirmation-checklist.md](supplementary/qa-field-confirmation-checklist.md)）
6. 继续 **「人力报价」**

### 3.4 ⑤ 人力报价

1. 进入 **「人力报价」**
2. 确认当前任务与项目信息
3. 勾选 **导出确认**
4. 点击 **「生成 Excel 报价初稿」**（真实生成，通常 < 1 分钟）
5. **下载** `.xlsx`；在 Excel 中进一步调整
6. 查看 **人天构成明细** 预览表（Demo 为 Mock，展示「交付物 → 贡献人天」形态）

> Demo 阶段 Excel 仅自动填充 **PM** 和 **Chassis** 两个 Function Sheet；构成明细与全 Function 在正式版提供。

## 4. 任务切换与历史记录

- 各页面顶栏 **「当前任务」** 下拉可切换最近 RFQ 分析记录
- **RFQ 分析** 页 **「最近分析」** 列表显示文件名、时间、处理状态
- 切换 tab（如去知识库再返回）后，系统会恢复上次选中的任务

## 5. 知识库（管理员）

> **定位：** 信任后台 + **检索实验室** — 验证历史资料如何进入系统、如何被检索、如何驱动 RFQ 对标。Demo **不包含**完整文档上传管理系统（upload UI 为 Phase 2）。

### 5.1 页面结构

| 区块 | 功能 |
|------|------|
| **概览** | 文档数、chunk 数、项目数、Function 覆盖、最近导入时间 |
| **运维** | **触发导入**；**导入说明**（文件夹规范） |
| **检索实验室** | 输入 query、调整 top_k、查看命中片段与来源文档路径 |
| **原子模块 Tab** | Phase 2 占位 |

页顶 Tag 标明当前为 Mock RAG 或真实向量检索。

### 5.2 导入历史文档

**推荐目录结构（Demo）：**

```
knowledge_base/
└── <项目名>/
    ├── rfq.docx
    ├── proposal.docx
    └── quote.xlsx
```

**Phase 2** 将支持 `manifest.json`，成套关联 RFQ / QA / 报价（见 [rag-design.md](supplementary/rag-design.md)）。

**操作步骤：**

1. 将历史项目文档放入服务器 `knowledge_base/<项目名>/`（Docker 卷路径见 [deployment-guide.md](deployment-guide.md)）
2. 进入 **「知识库」** → **刷新统计** 查看文档数
3. 点击 **触发导入** 执行向量索引（Toast 显示新增/跳过数量）
4. 在 **检索实验室** 输入关键词，验证能否命中预期片段

**Re-index：** Demo 阶段由 IT 执行 `scripts/ingest_documents.py`，无 Web UI。

### 5.3 60 秒 Demo 演示脚本（建议）

1. 打开 **知识库** → 指统计卡片：「N 篇文档、Chassis 覆盖最高」
2. 检索实验室输入与 RFQ 相关的 query → 展示片段 + 来源文件名
3. 切到 **RFQ 分析** 已完成任务 → 指相似项目表：「同一检索逻辑驱动对标」
4. 若为 Mock RAG Tag：「切换真实向量库后界面不变」

### 5.4 原子模块目录（Demo 占位）

正式版将在此浏览按 Function 拆解的历史方案模块。Demo 阶段为占位说明。

### 5.5 支持的文档

- Word：RFQ、技术方案、SOW
- Excel：历史报价、Q_A 清单
- PDF：Phase 2 ingest

## 6. 注意事项

| 事项 | 说明 |
|------|------|
| AI 是辅助 | 所有对外文件必须人工审核 |
| Demo 预览 | 方案与 QA 页 Mock 内容不可直接对外 |
| 低置信度 | 标红结果须重点校验 |
| Function 缺口 | 某 Function 无历史参考时须人工补充依据 |
| 文件格式 | Demo RFQ 仅支持 .docx |
| 明细保密 | Excel 人力明细仅内部使用 |

## 7. 常见问题

**Q: 上传后一直「解析中」？**  
A: 正常 1–5 分钟；超过 10 分钟请联系 IT 检查 Ollama。

**Q: 技术方案/QA 内容看起来是固定的？**  
A: Demo 为界面预览；正式版接入贵司历史库后由 AI 生成。

**Q: 切换页面后结果不见了？**  
A: 请用顶栏任务下拉或 RFQ 页「最近分析」重新加载任务。

**Q: Excel 部分人天为空？**  
A: Demo 仅 PM+Chassis；正式版支持全部 Function。

**Q: 知识库没有上传按钮？**  
A: Demo 通过文件夹放置 + **触发导入**；完整 upload UI 为 Phase 2。

**Q: 检索结果与 RFQ 对标不一致？**  
A: 两者应共用同一检索逻辑；若不一致请联系 IT 检查 `MOCK_RAG` 配置。
