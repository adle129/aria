# ARIA 智能应用平台 — 用户操作手册

**首期应用：** ARIA 报价助手  
**版本：** v1.5 · 2026-07-02  
**适用对象：** 报价工程师、知识库管理员  
**规格：** [客户版 v3.7](ARIA-报价助手-正式版交付方案与报价（客户版）.md) · [prod.md](../prod.md) v1.5 · [R1 验收说明](R1-知识库验收与检索评测说明（客户版）.md)

## 1. 系统简介

**ARIA**（Assisted Reasoning & Intelligence Applications）是本地部署的 **AI 智能应用平台**。当前版本交付 **报价助手**，覆盖 EDAG 报价流程的 **四大输出**：

| 输出 | 系统页面 |
|------|---------|
| 历史技术对标 | RFQ 分析 |
| 技术方案草案 | 技术方案 |
| 待澄清技术问题 | 澄清问题 |
| 人力报价预测 | 人力报价 |

**重要：** AI 输出仅为参考草稿，导出前请务必人工审阅确认。

**里程碑色标（正式版）：**

| 页面 | R1 期 | M3/M4/M5 验收后 |
|------|-------|----------------|
| `/knowledge`、RFQ 对标 | 正式 | 正式 |
| `/quote` Excel | Demo/部分 | M3 后正式 |
| `/qa`、`/proposal` | Demo 预览 | M4/M5 后正式 |

**Demo 说明：** 远程阿里云环境可能为 Mock LLM/RAG。详见 [demo-scope-brief.md](demo-scope-brief.md)。

## 2. 访问系统

- **内网地址：** http://aria.company.internal（或部署方提供的地址，如 http://localhost）
- **远程访问：** 先连接公司 VPN，再访问上述地址
- **浏览器：** 推荐 Chrome / Edge 最新版

## 3. 五步工作流程

```
① RFQ 分析 → ② 历史对标（同页） → ③ 技术方案 → ④ 澄清问题 → ⑤ 人力报价
                                                      ↑ 知识库（管理员后台）
```

每个业务页面顶部有 **当前任务** 栏与 **五步进度条**。请先上传 RFQ 并完成解析，再依次审阅各步 AI 草稿。

### 3.1 ① RFQ 分析

1. 进入左侧 **「RFQ 分析」**
2. 在 **「最近分析」** 中选择历史任务，或上传新的 `.docx` RFQ
3. 等待 AI 解析（约 **30s–2min** / 次，32B；正式版高峰可能 **排队**）
   - 页面显示 **进度**；若排队，显示 **您排第 N 位 / 预计等待 X 分钟**（具体 SLA **待客户确认 TBD**）
4. 查看 **Function 模块**、交付物、里程碑、§四开发范围
5. **（R1 正式版）** 审阅 AI 提出的 **技术维度清单**，可增删改后点击 **「确认维度清单」**
6. 查看 **技术维度对比表**（**Top-3** 相似历史项目；不足 3 个时系统提示）及置信度
7. 点击相似项目行可 **展开** 查看 RAG 命中片段与 **来源文档/位置**（章节、行号等）
8. 若系统 **未找到足够相似历史项目**，会明确提示「无足够依据，请人工补充」，**不会**编造参考项目
9. 若某 Function **无历史参考**，对比矩阵下方会显示警告，请重点人工补充
10. 编辑对比表 → **保存修订** → 勾选确认
11. 点击 **「下一步：技术方案」** 或左侧导航继续

**置信度：** 🟢 高 / 🟡 中 / 🔴 低（低置信度须重点人工核对）

### 3.2 ③ 技术方案（M5 · 正式版）

1. 系统按 RFQ **预填** Content Template（34 页）：里程碑、模块列表、按 scope 保留页组
2. 查看 **《Proposal 自动填充说明》** — 未自动填写的 slide 与原因
3. **Assumptions / Work Content 等技术正文** 在 PPT 中 **由工程师编写**
4. 详见 [m5-proposal-fill-spec.md](supplementary/m5-proposal-fill-spec.md)

### 3.3 ④ 澄清问题（M4 · 正式版）

1. 系统合并 Top-3 历史 Q_A（按 Area）并 **语义去重**
2. **影响程度**：源行有则保留，否则 AI 分类；**历史依据**：可追溯至项目与源文件行号
3. Author / Assumption / Answer 列导出时 **留空**
4. 详见 [m4-qa-merge-spec.md](supplementary/m4-qa-merge-spec.md)

### 3.4 ⑤ 人力报价（M3 · 正式版）

1. 系统按 RFQ **§四开发范围** 选最相似历史报价为 **人天锚点**
2. **抽取** scope 内 Function 岗位人天，按 **当前 RFQ 里程碑** 重排 Excel 时间轴（**非**复制历史项目日期）
3. 查看 **报价填充说明**（若有缺失 milestone 或 scope 无基线）
4. 详见 [m3-scope-match-spec.md](supplementary/m3-scope-match-spec.md)

## 4. 任务切换与历史记录

- 各页面顶栏 **「当前任务」** 下拉可切换最近 RFQ 分析记录
- **RFQ 分析** 页 **「最近分析」** 列表显示文件名、时间、处理状态
- 切换 tab（如去知识库再返回）后，系统会恢复上次选中的任务

## 5. 知识库（平台 · R1 验收台）

> **定位：** **R1 知识库验收与运营台**（管理员 + 验收会）；工程师日常以 `/rfq` 为主。详见 [R1 验收说明](R1-知识库验收与检索评测说明（客户版）.md)。

**向导五步：** 准备 Engagement → 更新索引 → 文档清单 → **检索验证** → **baselines 核对**

**正式版入库（R1 双路径）：**

1. **IT 目录批量（大批量历史库推荐）：** 将 `knowledge_base/<engagement_id>/` + `manifest.json` 放入 **内网** 数据盘 → 本页 **更新知识库索引**
2. **Web 小批量：** 知识库页 **上传 1 套或一次最多 5 套** 项目包（ZIP 或多文件）；缺 Q&A/报价时仍可入库并 **提示缺件**

**不含于 R1：** 运营级 upload 门户（拖拽整目录、断点续传）— 见 [平台演进路线 §4](平台知识库演进路线（客户版）.md)。

### 5.1 页面结构

| 区块 | 功能 |
|------|------|
| **入库与验证向导** | 四步：准备项目资料 → 更新索引 → 查看清单 → 检索验证（Demo / Phase 2 说明分开展示） |
| **资料概览** | 文档数、chunk 数、项目数、Function 覆盖、最近索引时间 |
| **文档清单** | 各文件路径、类型、大小、状态（已索引/待索引/失败；Excel 失败为 Demo 限制） |
| **历史资料检索** | 关键词、工程领域/文档类型筛选、命中片段与来源 |
| **原子模块 Tab** | Phase 2 占位 |

页顶 Tag：**平台能力**；Mock 环境另有 **演示数据** 提示。

### 5.2 导入历史文档

**Demo（当前）：** 将历史 **`.docx`** 放入 `knowledge_base/<项目名>/`，在本页 **更新知识库索引**。同一文件夹下的多份 docx 视为同一项目的弱关联。

**Phase 2（R1 起）：** **Engagement 项目包** — `manifest.json` 关联 RFQ、Q_A、报价三件套；支持 **Web ≤5 套/次** 或 IT 目录批量。

**推荐目录结构（Phase 2 目标）：**

```
knowledge_base/
└── <项目名>/
    ├── manifest.json
    ├── rfq.docx
    ├── qa.xlsx
    ├── quote.xlsx
    └── proposal.docx
```

**操作步骤（Demo）：**

1. 将 `.docx` 放入服务器 `knowledge_base/<项目名>/`（生产见 [deployment-guide.md](deployment-guide.md)）
2. 进入 **平台 → 知识库** → **更新知识库索引**
3. 在 **文档清单** 确认状态；若有失败，查看错误说明
4. 在 **检索实验室** 验证关键词能否命中预期片段

### 5.3 客户 Demo 演示脚本

完整 15–20 分钟流程见 **[demo-rehearsal-guide.md](demo-rehearsal-guide.md)**。

**知识库片段（约 3 分钟）：**

1. 指 **平台能力** Tag 与 **入库向导**
2. 展示 **文档清单** 与统计卡片
3. 检索实验室输入 query → 展示片段 + 来源
4. 切到 **RFQ 分析** 对标结果：「同一检索逻辑」

### 5.4 原子模块目录（Demo 占位）

正式版将在此浏览按 Function 拆解的历史方案模块。Demo 阶段为占位说明。

### 5.5 支持的文档

- Word：RFQ、技术方案、SOW
- Excel：历史报价、Q_A 清单
- PDF：Phase 2 ingest

## 6. 注意事项

| 事项 | 说明 |
|------|------|
| AI 是辅助 | 所有对外文件必须人工审核 |
| Demo 预览 | 方案与 QA 页 Mock 内容不可直接对外 |
| 低置信度 | 标红结果须重点校验 |
| Function 缺口 | 某 Function 无历史参考时须人工补充依据 |
| 文件格式 | Demo RFQ 仅支持 .docx |
| 明细保密 | Excel 人力明细仅内部使用 |

## 7. 常见问题

**Q: 上传后一直「解析中」？**  
A: 正常 1–5 分钟；超过 10 分钟请联系 IT 检查 Ollama。

**Q: 技术方案/QA 内容看起来是固定的？**  
A: Demo 为 Stub 预览；M4/M5 正式版分别按 [m4](supplementary/m4-qa-merge-spec.md) / [m5](supplementary/m5-proposal-fill-spec.md) 规格生成（M5 **不用** AI 写正文）。

**Q: 切换页面后结果不见了？**  
A: 请用顶栏任务下拉或 RFQ 页「最近分析」重新加载任务。

**Q: Excel 部分人天为空？**  
A: Demo 仅 PM+Chassis；正式版支持全部 Function。

**Q: 知识库没有大批量上传？**  
A: R1 支持 **Web 一次最多 5 套** + IT 目录批量；**运营级** 拖拽整目录上传为上线后可选增强。

**Q: 检索结果与 RFQ 对标不一致？**  
A: 两者应共用同一检索逻辑；若不一致请联系 IT 检查 `MOCK_RAG` 配置。

**Q: 发现引用不准，怎么告诉系统？**  
A: **验收期** 使用 [R1 检索评测记录表](R1-知识库验收与检索评测说明（客户版）.md) 逐条标注。**日常** 请修改对比表或确认参考项目后定稿。若已采购 **引用反馈 L1**（M6 后可选），可在知识库检索结果或 RFQ 相似项目行点击 **「不相关 / 引用不准」** — 系统 **记录反馈供管理员审查**，**不会** 自动修改大模型。

**Q: 资料越加越多，AI 会不会越用越准？**  
A: 资料多 → **可引用历史更全**（须规范入库并 **更新索引**）。**不会** 因此自动变准或变快。持续改进可选 [反馈运营包 L1/L2](supplementary/feedback-ops-pack（客户版）.md)。
