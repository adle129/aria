## 一、项目概述

在贵司内网私有化部署 **ARIA 智能应用平台**，首期交付 **报价助手** 应用，辅助报价工程师完成 RFQ 解析、历史项目对标、技术澄清、Proposal 模板预填与人力报价初稿。

- **原则：** AI 与历史资料输出供工程师 **审阅确认后定稿**；数字、日期、溯源以 **规则与算法** 为主，语义判断以 **本地大模型** 为辅（见 §1.2）
- **界面：** 中文
- **部署：** 本地大模型（Ollama + Qwen2.5），数据不出内网
- **平台价值：** 交付可扩展的 **Engagement 企业知识库** — 历史 RFQ、Q_A、报价 **一次入库、多环节复用**，为 M3–M5 与 future 应用提供 **同一数据底座**

### 1.1 产品卖点（平台 + 应用）

| 卖点 | 说明 |
|------|------|
| **内网私有化 AI 平台** | 非 SaaS；资料与模型均在贵司 GPU 服务器，满足 OEM/合资保密要求 |
| **Engagement 知识库** | 按 **完整报价项目包** 关联入库（manifest），不是散乱文件堆 |
| **历史锚定、非凭空生成** | M3/M4 以 **Top-3 相似项目** 为源；M5 **模板预填**；减少 AI 幻觉 |
| **可验收、可签字** | R1 检索评测 + baselines 对照；M5/M3 **填充缺口报告** 明示缺失 |
| **可扩展** | 同一 `${ARIA_DATA_ROOT}` 可挂接财务助手等应用（规划），见 [演进路线](./平台知识库演进路线（客户版）.md) |
| **工程师仍掌控定稿** | 维度清单确认、对比矩阵可编辑、Proposal 技术正文自写 |

> 对客一句话：**在内网建立「可运营的历史项目知识库 + 本地大模型」，报价助手是首个落地应用。**

### 1.2 AI 能力边界（本地大模型用在哪）

| 环节 | 本地 LLM | 向量检索（Embedding） | 规则/算法 |
|------|----------|----------------------|-----------|
| RFQ 解析、对标矩阵 | **核心** | 提供 Top-3 历史片段 | 里程碑等结构化校验 |
| M4 Q_A | **去重、影响程度补空** | R1 行级索引（验收/归档） | 合并、H 列溯源组装 |
| M3 报价 | **可选：scope→岗位行筛选** | 不用于选股 | ScopeMatch、**时间轴重映射**、人天计算 |
| M5 Proposal | **不用**生成正文 | 不用 | 模板预填 + 缺口报告 |
| R1 入库 | 可选 Area 归一化 | RFQ/Q_A 切块 | Excel/JSON 解析 |

**不做：** M5 四段式 AI 正文、Q_A 凭空造题、Excel 月列 LLM 自由填数、历史依据叙述编造。

**各环节自动化参考：**

| 环节 | 系统主要动作 | 工程师职责 |
|------|-------------|-----------|
| RFQ 对标 | Top-3 检索 + 维度确认 + 对比矩阵 | 确认矩阵与置信度 |
| M4 Q_A | Top-3 历史 Q_A **Area 合并 + 语义去重**；G/H 列按规格填充 | 编辑、补充、导出 |
| M3 报价 | Scope 选源 → **抽取岗位人天** → **按 RFQ 里程碑重排** Excel | 确认人天与汇总 |
| M5 方案 | Content Template 预填 + **填充报告** | **技术正文自写** |

## 三、知识库范围说明（R1 首期）

**R1 = Engagement 项目包知识库**，为 M3/M4/M5 提供 **统一关联数据**。

### 3.1 入库与使用

| 资料类型 | R1 入库 | 后期使用 |
|---------|--------|---------|
| **RFQ** | 章节切块 + 向量；§四 `development_scope` metadata | Top-3 对标；M3/M4/M5 选源 |
| **Q_A Excel** | **按行切块**（全 8 列 metadata）+ 向量 | M4：读 A/B/C 全表 Area 合并 |
| **报价 Excel** | **Sheet 级解析** → `manpower_baselines.json` + 源路径 | M3：ScopeMatch + 抽取 + 重映射 |
| **Proposal** | 可选；manifest 配对 RFQ | **不作 M5 生成**；归档/验证 |

**三件套（自动流程必需）：** RFQ + Q_A + 报价；缺任一项不参与 M3/M4 自动流程。

### 3.2 切块验收口径

| 资料 | R1 目标 |
|------|--------|
| RFQ | 章节 chunk + Top-3 检索 |
| Q_A | **每行 1 记录**；8 列可读；检索实验室可按 Area 过滤 |
| 报价 | baselines 数字与源 Excel 一致 |
| Proposal | 可选配对 |

**R1 不含：** 运营级 Web 上传门户、Hybrid/Rerank、细粒度权限（见 [演进路线](./平台知识库演进路线（客户版）.md)）。

### 3.3 入库方式（R1 双路径）

| 方式 | 说明 |
|------|------|
| **IT 目录批量** | `${ARIA_DATA_ROOT}/app/knowledge_base/<engagement_id>/` + `manifest.json` + `POST /knowledge/import`（**100+ 推荐**） |
| **Web 小批量** | `POST /knowledge/engagements/upload` — 单次 **≤5 套**；缺件提示 |

## 十一、工期延迟与算法风险（双方知悉）

计划 **约 20 周**（R1 起算）。各阶段 **贵司配合重要程度** 见 [附录 §3](./附录-模块能力与验收配合说明（客户版）.md#3-各阶段为何特别需要贵司配合)。下列场景可能导致 **日历顺延**（不自动增加软件开发费，范围变更除外）：

| 风险 | 影响 | 贵司可配合 |
|------|------|-----------|
| **签约前/后尚无真实 Engagement** | ScopeMatch、baselines 需样本到位后在 **R1 第 7–8 周** 调优 | 签约后 **1 周内** 提供 3–5 套脱敏 **三件套** |
| **M3 ScopeMatch 选源争议** | M3 验收反复 | M3 验收对 **≥3 个 RFQ** 的相似报价源 **书面确认** |
| RFQ **§四开发范围** 解析不稳 | M3/M5 受阻 | 提供标准 RFQ；参与 R1 调优 |
| 历史 Excel 与模板不一致 | 入库/M3 返工 | 签收模板 + 标准样本 |
| M0 未就绪 | R1 签字顺延 | 签约即采购 GPU、数据盘 |
| Engagement **缺 Q_A/报价** | M3/M4 不可用 | 三件套齐全 |
| Content Template 映射未确认 | M5 顺延 | M5 前书面确认 scope→slide |
| UAT 排期空档 | 各阶段顺延 | 每里程碑 2–3 人试用 |

**固定价 ¥18.3 万** 含 R1/M3 **算法 Spike 与样本到位后调优窗口**；新增映射规则、Hybrid 检索等 → **变更单**。
