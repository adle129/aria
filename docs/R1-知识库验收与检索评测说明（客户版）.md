## 写在前面 · 两个常用词

| 说法 | 含义 |
|------|------|
| **项目包（Engagement）** | **一套完整的历史报价项目资料**，按同一个历史项目打包关联，至少含 **RFQ + Q&A Excel + 人力报价 Excel**（称 **三件套**）。下文「项目包」与合同附件中的 Engagement **同义**。 |
| **第一期 / R1** | 知识库 + 上传 RFQ 找相似项目并生成对比表；**不含** 后面几步的 Excel/PPT 自动生成验收。 |

**和 100+ 历史项目的关系：** R1 签字用贵司提供的 **3–5 套金标准三件套** 做验收；100+ 项目可在 R1 后继续分批入库（IT 目录批量或网页小批量上传），**不必等 100+ 全部进库才签 R1**。

## 1. 验收目的（一句话）

第一期要证明四件事：

1. **历史项目包能正确进系统**（进库）  
2. **报价 Excel 里的人天数字读对了**（人天对照）  
3. **新 RFQ 能走通「找相似项目 → 出对比表」**（对标流程）  
4. **按约定题目检索，大部分能搜到对的**（检索评测）  

这四项是后面人力报价、澄清问题、技术方案 PPT 的 **共同数据底座**。

**第一期明确不含：** 第二期 Excel 生成、第三期 Q&A 导出、第四期 PPT 预填；运营级大批量上传门户；按个人感受评价 AI「够不够聪明」作为单独拒付理由（见主方案与附录）。

## 2. 项目包（Engagement）入库要求

### 2.1 三件套（每套项目包必需）

| 文件 | 说明 | 第一期用来做什么 |
|------|------|-----------------|
| **RFQ**（Word 或 PDF） | 客户询价/技术规格文件 | 切块入库；供 **找 3 个最相似历史 RFQ** |
| **Q&A Excel** | 贵司澄清问题清单模板格式 | 验证文件已关联、可被后续第三期读取 |
| **人力报价 Excel** | 贵司报价人力模板格式 | 解析为人天对照表，供 **数字核对** 与第二期参考 |

三份文件须 **归属同一历史项目**，系统按项目包关联，不是散乱单文件堆在一起。

### 2.2 可选资料

| 文件 | 说明 |
|------|------|
| **Technical Proposal（PPT）** | 可与 RFQ **配对归档** 备查；**第一期不验收** 第四期 PPT 自动生成的质量 |

### 2.3 资料怎么放进系统（两种方式）

| 方式 | 适合谁 | 怎么做 |
|------|--------|--------|
| **A · IT 目录批量（100+ 推荐）** | 贵司 IT 一次性导入大量项目 | IT 按入库规范把项目包放到服务器指定目录 → 管理员在 **知识库网页** 点 **「更新知识库索引」** |
| **B · 网页上传（单套/小批量）** | 管理员补录少量项目 | 在 **知识库网页** 点 **「上传项目包」**：**1 套** 或一次 **最多 5 套** → 上传后触发索引 |

**资料不完整时：** 允许先进库；导入报告须标明 **缺 Q&A 或缺报价** 以及对后续第二、三期的影响。

**第一期不含：** 拖拽整目录、断点续传、上传时 AI 自动识别、一次上传数十套以上的运营级门户。

> IT 目录路径、配置文件等技术细节见 [IT 基础设施说明](./customer-it-infrastructure.md)，业务读者可跳过。

## 3. 各类资料在验收里怎么查

| 资料 | 第一期要做到 | 验收时怎么查 |
|------|-------------|-------------|
| **RFQ** | 按章节入库，支持相似检索 | **检索试用** + **3 份 RFQ 对标流程** |
| **Q&A Excel** | 每行一条记录，8 列信息与模板一致 | 任选 1 套：行数与 Excel 有效行一致；按领域筛选能搜到 |
| **报价 Excel** | 解析为人天对照表，保留源文件路径 | **§4.2 数字对照**：与源 Excel 人工核对 |
| **技术方案 PPT（可选）** | 与 RFQ 配对归档 | 清单中可见即可；不要求第四期级检索效果 |

**「3 个最相似历史项目（Top-3）」：** 上传 RFQ 或输入技术描述时，系统按意思相近找出 **最相似的 3 个** 历史 RFQ 供对标。若样本库暂时不足 3 个，显示 1–2 个并提示，**不因此阻塞** 对标流程验收。

**第一期不含：** 「精确找词 + 智能相似」全文组合检索（属后续平台增强，需变更单另议）。

## 4. 功能验收清单（签字用）

验收会议建议 **逐项演示并打勾**。下列每条均含：**验什么 → 验收时做什么 → 勾选标准**。

---

### 4.1 进库 · 「样本有没有正确进系统」

**验什么：** 贵司提供的 **3–5 套金标准三件套** 是否完整进入知识库，且系统能识别各类文件。

**验收时做什么：**

1. 打开 **知识库网页**，查看 **导入报告** 与 **文档清单**  
2. 确认每套项目包的 RFQ、Q&A、报价（及可选 PPT）均在清单中  
3. 查看统计：四类资料（RFQ / Q&A / 报价 / 可选 PPT）数量合理  

**勾选标准：**

- [ ] **3–5 套** 项目包导入完成  
- [ ] 导入报告 **失败文件数 = 0**（若有已知例外，须 **双方书面认可**）  
- [ ] 知识库网页统计中，**四类资料** 均可见  

**客户感受：** 「我们的样本已经在系统里了，类型也对。」

---

### 4.2 人天对照 · 「报价 Excel 里的数字有没有读对」

**验什么：** 系统把历史报价 Excel 解析成 **人天对照表** 后，数字是否与 **源 Excel 一致**（规则解析 + 人工核对，不是 AI 猜数）。

**验收时做什么：**

1. 至少抽 **2 份** 历史人力报价 Excel  
2. 每份至少核对 **3 个功能模块（Function）** 的人天合计  
3. 在知识库网页 **人天对照预览**（或对照表导出）与 **源 Excel 逐项比对**  

**勾选标准：**

- [ ] ≥ **2 份** 报价 Excel × 每份 ≥ **3 个** 功能模块人天已核对  
- [ ] 系统展示数字与源 Excel **人工核对一致**  

**为什么重要：** 第二期人力报价依赖这些人天数据；第一期先证明 **「读 Excel 读对了」**。

---

### 4.3 RFQ 对标 · 「新 RFQ 能不能走通对标流程」

**验什么：** 上传 **新 RFQ** 后，完整走通：**解析 → 确认对比维度 → 生成 3 个最相似项目的对比表**。

**验收时做什么（重复 3 次，用 3 份脱敏 RFQ）：**

1. 上传 RFQ  
2. 查看系统结构化解析结果，工程师确认是否合理  
3. **确认对比维度**（如交付物、范围、里程碑等）  
4. 系统生成 **可编辑技术对比矩阵**  
5. 双方 **书面签字** 认可该次流程  

**勾选标准：**

- [ ] **3 份** 脱敏 RFQ 均完成上述全流程并 **有签字记录**  

**与 4.4 的区别：** 本条验 **整条业务链路**；4.4 验 **检索实验室里按固定题目搜得像不像**。

---

### 4.4 检索评测 · 「按约定题目考检索，≥12/15 及格」

**验什么：** 双方事先定好的检索题，系统在 **检索实验室** 返回的结果是否 **与期望相关**。

**验收时做什么：**

1. 使用双方在第 4 周前 **共同确认** 的 **≥15 道检索题**（基于 RFQ 片段、Q&A、报价相关描述；**不含** 第四期 PPT 方案正文生成题）  
2. 贵司工程师在检索实验室 **逐条试用**  
3. 填写 **《R1 检索评测记录表》**（见 §6）：每题记录问了什么、期望命中哪个项目/哪类文档、系统返回的前 3 条结果、判 **过/不过**、备注  
4. **截图与签字表一并存档**  

**勾选标准：**

- [ ] ≥ **15 道** 题已试用并记录  
- [ ] **≥12/15** 道判定为 **通过**（返回结果与期望 **相关**）→ 检索评测算 **整体通过**  
- [ ] 未通过的题：须在 R1 签字前 **修复至通过**，或 **书面说明** 接受降级范围  
- [ ] 任选 **1 套 Q&A**：8 列可读；记录条数与 Excel 有效行一致  

**谁出题：** 乙方提供预设题及期望结果初稿；**第 4 周前** 基于脱敏样本 **双方共同确认** 最终题集。

---

### 4.5 知识库网页 · 「验收和管理用的页面是否齐全」

**验什么：** 知识库管理页是否具备 R1 验收与日常管理所需功能。

**验收时做什么：**

1. 打开知识库网页，确认可见：**文档数量统计**、**已入库文件清单**、**检索试用区**、**人天对照表预览**  
2. **演示网页上传 1 套** 项目包：上传 → 清单可见 → 检索能命中  
3. （可选）演示一次 **小批量 ≤5 套** 上传  
4. 确认贵司 IT/管理员 **按本文步骤** 即可完成 R1 验收演示（无需改代码）  

**勾选标准：**

- [ ] 统计、清单、检索试用、人天对照预览 **均可使用**  
- [ ] **单套网页上传** 演示通过  
- [ ] （可选）小批量上传演示  
- [ ] 管理员可按本说明完成验收演示

## 5. R1 签字时要交什么

| # | 交付物 | 谁负责 |
|---|--------|--------|
| 1 | **《R1 检索评测记录表》** 签字扫描件（≥15 道题） | 双方工程师 |
| 2 | **人天对照数字核对表**（≥2 份报价 × 每份 ≥3 个功能模块） | 双方 |
| 3 | **导入报告**（失败文件数 = 0）截图或导出 | 开发方演示、客户确认 |
| 4 | **3 份 RFQ 对标** 签字记录 | 双方 |
| 5 | **环境就绪（M0）** 联合验收记录 | IT + 开发方 |

**说明：** 若进库、切块、人天解析等 **关键技术验证** 在内部预演中未通过，开发方 **不进入** 正式 R1 客户验收会议（避免浪费贵司试用时间）。正式验收以本章 §4 客户可感知的清单为准。
