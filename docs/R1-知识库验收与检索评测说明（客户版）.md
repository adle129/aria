## 写在前面 · 术语说明（业务读者必读）

> 下列说法均用 **日常业务语言** 书写。括号内编号（如 O-02a）仅供与合同附件对照，**验收时以「做什么、看到什么」为准**。

### 常用词

| 说法 | 含义 |
|------|------|
| **项目包** | **一套历史报价项目的全部资料**，按同一个历史项目打包关联。完整版至少含 **RFQ + Q&A Excel + 人力报价 Excel**（称 **三件套**）。 |
| **第一期 / R1** | 第一期里程碑：历史资料入库 + 上传新 RFQ 找相似项目并生成对比表；**签字后工程师即可日常做 RFQ 技术对标**。 |
| **金标准样本** | **≥5 套**资料齐全、已脱敏的「标准样板」，用于 **逐套**验收「系统有没有读对文件、读对数字」。 |
| **结构试点样本** | **10–20 套**已脱敏样本（**允许缺 Q&A 或缺报价**），用来提前发现「大批量入库时哪些格式容易出问题」。 |
| **贵司现有历史项目库** | 贵司积累的 **全部或大部分** 历史报价项目资料；**具体套数以双方《历史项目清点表》为准**（目前沟通约数十至百级，**合同不写死数字**）。 |
| **清点表** | 签约后 2 周内双方填写的表格：计划入库多少套、多少套资料齐全、哪些常见缺件。 |
| **三件套齐全 / 缺件** | **齐全（金级）**：RFQ + Q&A + 报价都有。**缺件（银级/铜级）**：例如只有 RFQ、缺报价—— **仍可入库**，但第二期 Excel、第三期 Q&A 等 **自动功能会受影响**，导入报告会写明。 |
| **人天对照表** | 系统把历史报价 Excel 里的 **各功能模块人天数** 读出来，供您与 **源 Excel 人工核对**（不是 AI 猜数）。 |
| **Top-3（三个最相似项目）** | 上传新 RFQ 时，系统从历史库中找出 **意思最相近的 3 个** 历史 RFQ，供生成技术对比表。 |
| **检索试用 / 检索实验室** | 知识库网页里的 **「试搜一下」区域**：输入一段技术描述，看系统能否找到相关的历史 RFQ、Q&A 或报价片段。 |
| **更新知识库索引** | 资料放进服务器后，管理员在网页上点一次 **「让系统重新扫描并建立检索目录」**（类似图书馆新书编目，不是改文件本身）。 |
| **导入报告** | 批量入库完成后系统出具的 **成功/失败/缺件清单**；默认要求清点表范围内 **≥90% 项目包入库成功**，例外须双方书面认可。 |
| **签完即用** | 第一期签字后，工程师 **无需等到 20 周全部功能上线**，即可在内网用真实历史库做 RFQ 技术对标。 |

### 两阶段怎么配合（不用记 IT 术语）

| 阶段 | 用什么资料 | 在哪里做 | 大约时间 |
|------|-----------|---------|---------|
| **前期 · 样本验证** | ≥5 套 **完整**金标准 + 10–20 套结构试点（**已脱敏**，可缺件） | 乙方开发联调 + 贵司提供脱敏副本 | 第 1–5 周 |
| **后期 · 内网正式入库** | 贵司 **现有历史项目库**（**原始资料不出公司内网**） | **仅在贵司内网服务器** | 第 5–8 周落盘；**第 7–8 周验收签字** |

**数据安全：** 含客户真实信息的 RFQ/报价/Q&A **不离开贵司内网**；乙方不要求把全库拷到开发方电脑。第一期 bulk 验收 **在贵司内网** 演示。

**和贵司现有历史项目库的关系（摘要）：**

> 历史项目 **总量以贵司实际清点为准**。**不要求** 每套都有完整三件套；缺件项目可入库，报告标明对后续功能的影响。签字时库内建议 **≥15 套** 历史 RFQ 可被检索，Top-3 对标才有足够区分度。

**合同附件编号对照（可选）：** 金标准 = O-02a · 结构试点 = O-02b · 内网批量入库 = O-02c · 清点表 = O-02d。

## 1. 验收目的（一句话）

第一期要证明五件事：

1. **金标准项目包能正确进系统**（≥5 套，进库）  
2. **内网批量历史库已导入并可检索**（清点表范围内的 **导入报告**）  
3. **报价 Excel 里的人天数字读对了**（人天对照）  
4. **新 RFQ 能走通「找相似项目 → 出对比表」**（对标流程；**签完即用**）  
5. **按约定题目检索，大部分能搜到对的**（检索评测）  

这四项是后面人力报价、澄清问题、技术方案 PPT 的 **共同数据底座**。

**第一期明确不含：** 第二期 Excel 生成、第三期 Q&A 导出、第四期 PPT 预填；拖拽整文件夹上传、断点续传等 **运营级大批量上传门户**；开发用内部调试页面；网页「引用不准」一键反馈按钮（属后续可选增强）；按个人感受评价 AI「够不够聪明」作为单独拒付理由（见主方案与附录）。

## 2. 项目包（Engagement）入库要求

### 2.1 三件套（每套项目包必需）

| 文件 | 说明 | 第一期用来做什么 |
|------|------|-----------------|
| **RFQ**（Word 或 PDF） | 客户询价/技术规格文件 | 切块入库；供 **找 3 个最相似历史 RFQ** |
| **Q&A Excel** | 贵司澄清问题清单模板格式 | 验证文件已关联、可被后续第三期读取 |
| **人力报价 Excel** | 贵司报价人力模板格式 | 解析为人天对照表，供 **数字核对** 与第二期参考 |

三份文件须 **归属同一历史项目**，系统按项目包关联，不是散乱单文件堆在一起。

### 2.2 可选资料

| 文件 | 说明 |
|------|------|
| **Technical Proposal（PPT）** | 可与 RFQ **配对归档** 备查；**第一期不验收** 第四期 PPT 自动生成的质量 |

### 2.3 资料怎么放进系统（两阶段 + 两种方式）

**两阶段数据路径：**

| 阶段 | 数据 | 环境 | R1 时间 |
|------|------|------|---------|
| **P1 · 脱敏验证** | ≥5 套 **完整**金标准 + 10–20 套结构试点（**可缺件**） | 乙方开发 / 贵司提供的 **已脱敏** 副本 | 第 1–5 周 |
| **P2 · 内网生产入库** | 贵司 **现有历史项目库**（**原始资料不出网**） | **仅贵司内网** GPU 服务器 + 数据盘 | 第 5–8 周 import；**第 7–8 周验收** |

| 方式 | 适合谁 | 怎么做 |
|------|--------|--------|
| **A · IT 目录批量（大批量历史库推荐）** | 贵司 IT 一次性导入大量项目 | IT 按入库规范把项目包放到 **内网** 服务器指定目录 → 管理员在 **知识库网页** 点 **「更新知识库索引」** |
| **B · 网页上传（单套/小批量）** | 管理员补录少量项目 | 在 **知识库网页** 点 **「上传项目包」**：**1 套** 或一次 **最多 5 套** → 上传后系统自动建立检索目录 |

**资料不完整时：** 允许 **金/银/铜** 分级先进库；导入报告须标明 **缺 Q&A 或缺报价** 以及对后续第二、三期的影响。

**第一期不含：** 拖拽整文件夹、断点续传、一次上传数十套以上的 **运营级上传门户**（属后续可选增强）。

> IT 目录路径、服务器文件夹命名等技术细节见 [IT 基础设施说明](./customer-it-infrastructure.md)，**业务读者可跳过**。

### 2.4 第一期知识库网页：您能在界面上做什么

第一期交付的是 **「知识库管理页」**（工程师菜单中的 **「知识库」**），用于 **验收、管理和试搜历史资料**。它与 **「RFQ 分析」页** 共用同一套历史库检索能力，但分工不同：

| 页面 | 第一期主要用途 |
|------|---------------|
| **知识库管理页** | 看入库情况、试搜历史、核对人天数字、上传少量补录 |
| **RFQ 分析页** | 上传 **新 RFQ**，走 **找 Top-3 → 确认维度 → 生成对比表** 的完整对标流程 |

**知识库管理页 — 第一期包含的界面功能：**

| 功能区块 | 您能看到 / 能做什么 | 验收时怎么用 |
|---------|-------------------|-------------|
| **资料概览** | 已入库多少套项目、多少份 RFQ / Q&A / 报价；最近何时更新过检索目录 | 确认历史库「规模够不够用」（建议 **≥15 套 RFQ** 可被检索） |
| **文档清单** | 每套项目下有哪些文件、是否入库成功、是否缺件 | 对照金标准 5 套是否都在列表中 |
| **导入 / 入库报告** | 批量入库的成功数、失败数、缺件说明 | 核对清点表范围内 **≥90%** 是否成功（或书面例外） |
| **上传项目包** | 网页上传 **1 套** 或一次 **最多 5 套**；缺件时有提示 | 验收时演示补录 1 套 |
| **更新知识库索引** | IT 把大量资料放入服务器指定文件夹后，管理员 **点一次** 让系统重新扫描 | 大批量历史库入库后的必做步骤 |
| **检索试用区** | 输入一段 **技术描述**（如「MEB 副车架仿真范围」），看系统返回的 **前几条相关片段** 及 **来自哪个历史项目** | **15 条检索评测** 在此操作；判结果是否 **与期望相关** |
| **筛选条件** | 可限定 **文档类型**（RFQ / Q&A / 报价）或 **工程领域**（如 Chassis） | 缩小检索范围，避免结果太杂 |
| **人天对照预览** | 查看系统从报价 Excel 读出的 **各功能模块人天数**，与源 Excel 比对 | **§4.2** 数字核对 |

**RFQ 分析页 — 与历史检索相关的功能（第一期正式验收）：**

| 功能 | 说明 |
|------|------|
| **上传新 RFQ** | 解析本次询价的技术范围与交付物 |
| **Top-3 相似项目** | 自动列出 **3 个最相似** 的历史 RFQ（库内不足 3 个时显示 1–2 个并提示，**不阻塞验收**） |
| **确认对比维度** | 工程师勾选本次要对标的 **工作维度**（约 100 项基准清单） |
| **技术对比矩阵** | 生成可编辑的 **新 RFQ vs 历史 Top-3** 对比表 |

**第一期界面明确不含（勿在验收会中要求演示）：**

| 不含项 | 说明 |
|--------|------|
| 开发调试页 / 切块浏览器 | 仅供乙方开发内部使用，**不对客户开放** |
| 网页「这条结果不相关」按钮 | 第一期用 **检索评测记录表** 人工标注；一键反馈属后续可选 |
| 拖拽整目录、断点续传 | 大批量仍走 **IT 放文件夹 + 网页点更新索引** |
| 按项目代号 **精确搜名字** | 第一期主要是 **按技术意思找相似**；精确找名 + 相似组合属后续增强 |
| 澄清问题 / 人力 Excel / PPT 正式生成 | 第二、三、四期里程碑；第一期仅为 **Demo 预览** 或不含 |

## 3. 各类资料在验收里怎么查

| 资料 | 第一期要做到 | 验收时怎么查 |
|------|-------------|-------------|
| **RFQ** | 按章节入库，支持相似检索 | **检索试用** + **3 份 RFQ 对标流程** |
| **Q&A Excel** | 每行一条记录，8 列信息与模板一致 | 任选 1 套：行数与 Excel 有效行一致；按领域筛选能搜到 |
| **报价 Excel** | 解析为人天对照表，保留源文件路径 | **§4.2 数字对照**：与源 Excel 人工核对 |
| **技术方案 PPT（可选）** | 与 RFQ 配对归档 | 清单中可见即可；不要求第四期级检索效果 |

**「3 个最相似历史项目（Top-3）」：** 上传 RFQ 或输入技术描述时，系统按 **意思相近** 找出 **最相似的 3 个** 历史 RFQ 供对标。知识库内 **至少 5 套、建议 15 套以上** 可被检索的历史 RFQ 时，Top-3 才有排序与差异意义。若暂时不足 3 个，显示 1–2 个并提示，**不因此阻塞** 对标流程验收。

**第一期不含：** 「精确找词 + 智能相似」全文组合检索（属后续平台增强，需变更单另议）。

## 4. 功能验收清单（签字用）

验收会议建议 **逐项演示并打勾**。下列每条均含：**验什么 → 验收时做什么 → 勾选标准**。

---

### 4.1 进库 · 「金标准有没有正确进系统」（O-02a）

**验什么：** 贵司提供的 **≥5 套金标准三件套** 是否完整进入知识库，且系统能识别各类文件。

**验收时做什么：**

1. 打开 **知识库网页**，查看 **导入报告** 与 **文档清单**  
2. 确认 **5 套** 项目包的 RFQ、Q&A、报价（及可选 PPT）均在清单中  
3. 查看统计：四类资料（RFQ / Q&A / 报价 / 可选 PPT）数量合理  

**勾选标准：**

- [ ] **≥5 套** 金标准项目包导入完成  
- [ ] 金标准导入报告 **失败文件数 = 0**（若有已知例外，须 **双方书面认可**）  
- [ ] 知识库网页统计中，**四类资料** 均可见  

**客户感受：** 「我们的金标准样本已经在系统里了，类型也对。」

---

### 4.1b 批量历史库 · 「内网大批量入库是否完成、能否搜到」（配合项 O-02c）

**验什么：** 贵司 **现有历史项目库**（**清点表** 确认的范围）是否已通过 **内网 IT 放文件夹 + 管理员更新检索目录** 进入系统（缺件项目可 **银/铜** 分级）。

**验收时做什么（在贵司内网环境）：**

1. 查看 **批量导入报告**（成功/失败/缺件/等级）  
2. 资料概览：**可被检索的历史 RFQ 有多少套**（建议 **≥15**）  
3. 确认清点表范围内 **≥90%** 项目包入库成功，或双方 **书面认可** 例外清单  

**勾选标准：**

- [ ] 批量导入报告已出具  
- [ ] **≥90%** 项目包入库成功（或书面例外）  
- [ ] 库内 **≥15 套** 历史 RFQ 可被检索（推荐；不足时须书面说明降级范围）

---

### 4.2 人天对照 · 「报价 Excel 里的数字有没有读对」

**验什么：** 系统把历史报价 Excel 解析成 **人天对照表** 后，数字是否与 **源 Excel 一致**（规则解析 + 人工核对，不是 AI 猜数）。

**验收时做什么：**

1. 至少抽 **2 份** 历史人力报价 Excel  
2. 每份至少核对 **3 个功能模块（Function）** 的人天合计  
3. 在知识库网页 **人天对照预览**（或对照表导出）与 **源 Excel 逐项比对**  

**勾选标准：**

- [ ] ≥ **2 份** 报价 Excel × 每份 ≥ **3 个** 功能模块人天已核对  
- [ ] 系统展示数字与源 Excel **人工核对一致**  

**为什么重要：** 第二期人力报价依赖这些人天数据；第一期先证明 **「读 Excel 读对了」**。

---

### 4.3 RFQ 对标 · 「新 RFQ 能不能走通对标流程」

**验什么：** 上传 **新 RFQ** 后，完整走通：**解析 → 确认对比维度 → 生成 3 个最相似项目的对比表**。

**验收时做什么（重复 3 次，用 3 份脱敏 RFQ）：**

1. 上传 RFQ  
2. 查看系统结构化解析结果，工程师确认是否合理  
3. **确认对比维度**（如交付物、范围、里程碑等）  
4. 系统生成 **可编辑技术对比矩阵**  
5. 双方 **书面签字** 认可该次流程  

**勾选标准：**

- [ ] **3 份** 脱敏 RFQ 均完成上述全流程并 **有签字记录**  

**与 4.4 的区别：** 本条验 **整条业务链路**；4.4 验 **检索实验室里按固定题目搜得像不像**。

---

### 4.4 检索评测 · 「按约定题目考检索，≥12/15 及格」

**验什么：** 双方事先定好的检索题，系统在 **检索实验室** 返回的结果是否 **与期望相关**。

**验收时做什么：**

1. 使用双方在第 4 周前 **共同确认** 的 **≥15 道检索题**（基于 RFQ 片段、Q&A、报价相关描述；**不含** 第四期 PPT 方案正文生成题）  
2. 贵司工程师在检索实验室 **逐条试用**  
3. 填写 **《R1 检索评测记录表》**（见 §6）：每题记录问了什么、期望命中哪个项目/哪类文档、系统返回的前 3 条结果、判 **过/不过**、备注  
4. **截图与签字表一并存档**  

**勾选标准：**

- [ ] ≥ **15 道** 题已试用并记录  
- [ ] **≥12/15** 道判定为 **通过**（返回结果与期望 **相关**）→ 检索评测算 **整体通过**  
- [ ] 未通过的题：须在 R1 签字前 **修复至通过**，或 **书面说明** 接受降级范围  
- [ ] 任选 **1 套 Q&A**：8 列可读；记录条数与 Excel 有效行一致  

**谁出题：** 乙方提供预设题及期望结果初稿；**第 4 周前** 基于脱敏样本 **双方共同确认** 最终题集。
