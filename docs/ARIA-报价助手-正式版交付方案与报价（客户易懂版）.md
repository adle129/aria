## 一、项目要解决的问题

### 1.1 贵司业务场景

EDAG 作为车辆工程服务提供商，报价工作以 **技术方案** 为核心——客户提供 RFQ（含技术规格、边界条件、交付物清单），报价团队需据此完成技术澄清、Tech Proposal 撰写、历史对标与人天估算。这一链路目前 **高度依赖工程师的个人经验**。

### 1.2 当前主要痛点

| 痛点 | 具体表现 |
|------|---------|
| **查找历史资料耗时长** | 同类项目资料分散在不同文件夹、不同人手中；每次报价都要重新翻找历史 RFQ、Q&A、报价 Excel、Tech Proposal PPT |
| **重复性手工工作多** | 从 RFQ 中逐条提取功能模块、交付物、里程碑，再分别填入对标表、Q&A 清单、PPT 和 Excel——**同一份 RFQ 信息要在多种文档里重复整理** |
| **多格式文档难以比对** | 历史资料以 Word、PDF、Excel、PPT 等不同格式保存，无法结构化对照；常说「和 X 项目类似」，但 **难以量化差异**，人工比对耗费大量时间 |
| **依赖个人经验、易漏项** | 待澄清技术问题靠工程师回忆，常遗漏关键假设（如边界载荷未定义、交付物格式未明确）；新人上手慢，考虑维度 **不够全面** |
| **技术方案难以复用** | 每个新项目往往从零撰写 Tech Proposal，无法系统化引用历史项目中 **已验证** 的相似技术模块 |
| **人天估算缺乏锚点** | Excel 人天多凭经验估算，与 RFQ 交付物清单、历史实际人天 **缺乏可追溯的对应关系** |

### 1.3 ARIA 与本项目

**ARIA**（Assisted Reasoning & Intelligence Applications，智能应用平台）是部署在贵司内网的 **AI 智能应用平台**，统一提供 **历史项目知识库、本地大模型与智能检索** 能力；后续更多应用可在同一平台扩展复用。

**ARIA 报价助手** 是首期落地应用，提供 **中文网页五步流程**：上传 RFQ 后，系统借助本地 AI 与历史项目资料库，自动生成各环节 **参考草稿**；工程师在网页上核对、修改、确认后再导出正式文件。**资料与 AI 均在贵司内网处理**，不调用公有云 API。

```
① RFQ 分析 → ② 技术方案 → ③ 澄清问题 → ④ 人力报价
                    ↑
           知识库（历史项目资料，平台共享）
```

对应贵司期望的四大输出方向：

| 期望输出 | 报价助手对应环节 |
|---------|----------------|
| 待澄清技术问题清单 | ③ 澄清问题 |
| 技术方案草案（Tech Proposal） | ② 技术方案 |
| 历史技术对标报告 | ① RFQ 分析（含对标矩阵） |
| 人天预测 Excel | ④ 人力报价 |

**核心原则（请务必知悉）：**

- 系统输出的是 **参考草稿**，不是可直接发给客户的终稿  
- 数字、日期、技术结论须 **工程师确认**  
- 澄清问题来自 **历史同类项目**，不凭空编造  
- 所有资料与 AI 推理在 **贵司内网** 完成  

### 1.4 人机分工共识（与贵司期望一致）

贵司与乙方共识：**ARIA 报价助手是辅助起草工具，不是自动报价系统。**

| 分工 | 说明 |
|------|------|
| **系统（AI + 历史资料）** | 目标产出约 **50%–70%** 可参考内容：RFQ 结构化解析、相似项目检索、历史 Q&A 合并、模板预填、人天初稿等 |
| **报价工程师** | 约 **30%–50%** 须 **审阅、修改、补充后定稿**：技术方案正文、Author/Answer、人天与商务结论等 |
| **责任边界** | **对外正式文件由工程师负责**；系统输出均为参考草稿，导出前须确认 |

乙方 **不承诺** 本地大模型每次输出 100% 准确或零误差；验收以 **双方书面确认的里程碑标准** 为准（见技术版附件），不以「AI 主观满意度」单独作为拒付或无限返工依据。

## 二、系统能帮您做什么

以下按报价日常流程说明。**您只需关心：上传什么、系统帮您做什么、最后拿到什么文件。**

| 业务环节 | 系统帮您做什么 | 您拿到的文件 | 工程师仍须做 |
|---------|---------------|-------------|-------------|
| **RFQ 理解** | 自动读出功能模块、交付物、里程碑、开发范围 | 网页结构化报告 | 核对解析是否准确 |
| **历史对标** | 从资料库找出 **3 个最相似的历史 RFQ**；**先请您确认对比维度**，再生成对比表 | 可编辑的技术对比矩阵 | 确认维度、修改矩阵、判断置信度 |
| **澄清问题** | 合并相似历史项目的 Q&A，去掉重复题；**不凭空编造新问题** | `Q_A_*.xlsx`（贵司 Q&A 模板格式） | 补充 Author、Answer 等需人工填写的列 |
| **技术方案** | 按贵司 **34 页 Content Template** 预填封面、里程碑、模块相关页面；与本次 scope 无关的模块页删除 | `.pptx` + **《哪些页已填/未填说明》** | **技术正文（Assumptions、Work Content 等）由工程师在 PPT 中自行编写** |
| **人力报价** | 自动选出与当前 RFQ 最相似的历史报价作参考，抽取各岗位人天，**按当前 RFQ 的里程碑日期重新排布**（不是整表复制旧项目日期） | `报价人力_*.xlsx` + 填充说明 | 确认人天数、汇总与最终报价 |
| **知识库** | 将历史 RFQ、Q&A、报价 Excel **按完整项目打包入库**，供以上各环节统一调用 | 网页检索与验收界面；**可 Web 上传单套/小批量（≤5 套）** 或 IT 目录批量导入 | 提供脱敏后的历史项目资料 |

### AI 能做什么、不做什么（简明版）

| 会用 AI 辅助 | 不用 AI 代替 |
|-------------|-------------|
| 阅读 RFQ 文字、提取结构化信息 | 撰写技术方案正文 |
| 查找最相似的历史项目 | 凭空编造澄清问题 |
| 合并、去重历史 Q&A | 在 Excel 月列上随意填数字 |
| 辅助判断问题影响程度（有历史依据时） | 编造「历史依据」叙述 |

**历史锚定原则：** 人力报价与澄清问题清单均以 **相似历史项目** 为来源，减少 AI「凭空发挥」。

### 第一期知识库：支持怎样的检索？（客户可读）

第一期（R1）完成后，历史项目资料入库，并在 **RFQ 对标** 与 **知识库检索实验室** 中使用。首期检索方式如下：

| 能力 | 首期是否提供 | 客户可理解的说法 |
|------|-------------|-----------------|
| **智能相似检索** | **是** | 输入一段 RFQ 文字或技术描述（如「MEB 平台副车架」），系统按 **意思相近** 从历史项目中找出 **最相似的 Top-3**，用于对标矩阵 |
| **按条件筛选** | **是** | 可限定 **文档类型**（RFQ / Q&A / 报价）或 **工程领域**（如 Chassis、CAE），缩小检索范围 |
| **报价数字对照** | **是** | 历史报价 Excel 解析为 **结构化人天基线**，可与源 Excel **人工核对**，不依赖大模型填数 |
| **项目包 Web 上传** | **是** | 知识库页 **上传 1 套** 或一次 **最多 5 套** 历史项目包（ZIP 或多文件）；缺 Q&A/报价时仍可入库并 **提示缺件** |
| **精确找词 + 智能相似 组合检索** | **否** | 全文级组合检索；**不含于 R1**；需要时 **变更单** 另议 |

**说明：**

- 检索实验室中的「检索词」指 **技术描述或短语**，系统通过 **智能相似匹配** 找资料，**不是** Excel 式的逐字精确匹配。  
- 相似度会显示 **高 / 中 / 低** 提示；**低置信度须工程师重点人工核对**。  
- 第一期验收含 **≥15 条检索评测** 与 **3 份 RFQ 对标流程** 签字（详见 [R1 验收说明](./R1-知识库验收与检索评测说明（客户版）.md)）；**第 7–8 周** 专门用于贵司真实数据联合调优与验收签字（已含在第一期 8 周规划内）。

### 第一期知识库网页：界面上能做什么

> 详细验收步骤见 [R1 验收说明 §2.4](./R1-知识库验收与检索评测说明（客户版）.md)。下列为 **业务负责人速览**。

| 您在菜单里打开 | 能做什么 |
|---------------|---------|
| **知识库** | 看有多少历史项目已入库；查每套文件是否成功；**试搜**历史资料；**核对**报价 Excel 人天是否读对；上传 **1～5 套** 补录；IT 大批量放文件后 **点一次更新检索目录** |
| **RFQ 分析** | 上传 **新 RFQ** → 系统自动找 **3 个最相似历史项目** → 您 **确认对比维度** → 生成 **技术对比表**（第一期签字后即可日常使用） |

**第一期网页不含：** 开发调试页、拖拽整文件夹上传、网页「结果不准」一键反馈、按项目代号精确搜名字（后续可选增强）。

#### 贵司 IT 需自行采购的服务器（推荐配置）

本项目软件开发报价 **不含** 下列硬件与网络设备。正式在内网运行 ARIA 报价助手（本地大模型 + 历史项目知识库），建议贵司 IT 采购 **1 台 GPU 服务器 + 独立数据盘**，配置如下（**推荐生产档**）：

| 部件 | 推荐配置 | 用途说明 |
|------|---------|---------|
| **GPU 显卡** | NVIDIA **RTX 4090 24GB × 1** | 运行本地大模型（RFQ 解析、对标、Q&A 等 AI 能力） |
| **CPU** | **32 核** 级（服务器级处理器） | 应用服务、数据库、文档解析 |
| **内存** | **128 GB**（建议 ECC） | 并发处理 RFQ、知识库检索 |
| **系统盘** | **1 TB NVMe SSD** | 操作系统、ARIA 应用程序（可重装） |
| **独立数据盘** | **≥ 4 TB，建议 RAID1** | 存放历史项目资料、数据库、向量索引、大模型文件、每日备份（**核心业务数据，不可丢失**） |
| **操作系统** | **Ubuntu Server 22.04 LTS** | 与交付文档一致，便于部署与运维 |
| **网络** | 内网访问 + **VPN**（如需远程） | 报价工程师浏览器访问；**不应对公网开放** AI 服务端口 |

- 推理：**Qwen2.5**（推荐 32B 量化版，4090 可运行）  
- 检索：**nomic-embed-text**（文本向量化，用于找相似历史项目）  

**预算参考：** 含 RTX 4090 的推荐整机约 **6–10 万元人民币**（视品牌、盘位、是否含 UPS/机柜等而定，以贵司实际采购为准）。

**说明：**

- 以上为 **1 台服务器** 即可满足首期报价助手 + 知识库；后续用户增多或上线更多应用，再评估加 GPU 或限流。  
- 远程 Demo 体验环境（无 GPU）**不能替代** 上述生产服务器；正式版须在内网 GPU 环境验收。  
- 硬件安装、驱动、Docker、大模型下载等由 **贵司 IT 主责**；开发方提供配置清单与远程协助（约 2 人日，含在第一期价款内）。详细 IT 规格见 [IT 基础设施说明](./customer-it-infrastructure.md)。

**配置档位参考（供 IT 选型）：**

| 档位 | GPU | 内存 | 数据盘 | 适用 | 预算参考 |
|------|-----|------|--------|------|---------|
| 基础版 | 无或 ≥16GB 显卡 | 64 GB | 4 TB | 仅小规模试用 / 小模型 | 约 2–4 万 |
| **推荐版 ★** | **RTX 4090 24G ×1** | **128 GB** | **≥4 TB RAID1** | **首期正式生产（建议采购此档）** | **约 6–10 万** |

## 七、这是预估算 — 工期与费用可能受影响的风险

> **免责声明：** 本章所列时间与费用，是在 **当前 Demo 反馈与方案信息** 下的 **预估算**。实际进度可能因贵司样本到位时间、IT 环境准备、工程师试用排期而 **顺延**；若签约后增加功能、更换模板或扩大范围，须通过 **变更单** 另行评估工期与费用。  
>  
> 固定价 **¥18.3 万** 已含一定算法调优空间；**不含** 贵司侧长时间等待、多轮大范围需求变更所增加的软件开发工作。

### 关于本地大模型与检索效果（重要）

- **本地大模型具有不确定性：** 受模型版本、Prompt、样本质量影响，解析与去重结果 **可能因 RFQ 不同而略有差异**；乙方 **不保证** 100% 准确或每次完全一致。  
- **第一期检索为智能相似匹配（Top-3）：** 对项目代号、专有名词的「精确命中」可能不如后续「精确找词 + 智能相似」组合检索；须结合工程师核对与评测验收。  
- **效果依赖样本：** 历史项目包越标准、越齐全，检索与对标越稳；签约后 **1 周内** 提供样本至关重要。  
- **验收口径：** 以 **书面里程碑标准**（R1 评测表、baselines 对照、对标流程）为准，**不以** 「AI 还不够聪明」单独作为拒付理由；超出标准的新能力需求走 **变更单**。

| 可能情况 | 对进度的影响 | 建议贵司配合 |
|---------|-------------|-------------|
| **本地大模型解析/检索效果未达预期** | 第一期 **7–8 周** 加大联合调优；若仍不足则顺延 | 提供标准 RFQ 样本；参与检索评测签字 |

| 签约后尚无真实历史项目样本 | 第一期 **7–8 周** 无法有效调优，整体顺延 | 签约后 **1 周内 ≥5 套**金标准 + **2 周内**清点表 |
| 服务器/数据盘晚于第 **4** 周才到位 | 第一期 **无法在第 8 周内网验收**，整体顺延 | **签约即启动** IT 采购 |
| 历史 Excel 格式与签收模板不一致 | 入库或报价生成返工 | 签约时锁定模板 + 提供标准样本 |

| 签约后要求加功能、改模板 | 工期与费用另估 | 以签约范围清单为准 |

**什么情况下可能 **增加费用**（变更单）：** 新增功能模块、PPT 页数大幅增加、精确找词与智能相似组合检索、代贵司整理首批历史项目包等。
