## 1. 总览（按报价流程）

括号内为合同里程碑编号，便于与付款节点对照。

| 阶段 | 业务名称 | 完成后您能用上什么 | 系统帮您做 / 您仍须做（摘要） |
|------|---------|-------------------|------------------------------|
| **第一期（R1）** | 知识库 + RFQ 对标 | 历史项目入库；上传 RFQ 可找相似项目并生成对比表 | 系统：读 RFQ、找 **3 个最相似历史项目**、生成对比表 · **您：确认对比维度与表格内容** |
| **第二期（M3）** | 人力报价 Excel | 下载按 **当前 RFQ 日期** 排好的人力 Excel | 系统：选最相似历史报价作参考、抽取人天并重排日期 · **您：确认人天与汇总** |
| **第三期（M4）** | 澄清问题清单 | 导出符合贵司模板的 Q&A Excel | 系统：合并相似历史 Q&A、去重 · **您：补充作者、答复等须人工填写的列** |
| **第四期（M5）** | 技术方案 PPT | 下载预填 PPT + **哪些页已填/未填说明** | 系统：按模板预填封面、里程碑、模块相关页 · **您：技术正文自行编写** |
| **上线（M6）** | 培训与移交 | 五步全流程走通 + 运维文档 | 系统：集成联调 · **您：组织试用、参加培训、参与备份演练** |

**核心原则：** 系统输出均为 **参考草稿**；对外正式文件由 **贵司工程师审阅确认后定稿**。

## 2. 分阶段验收配合（签字用）

### 2.1 第一期 · 知识库（R1）

| 项目 | 内容 |
|------|------|
| **系统主要能力** | 将历史项目按规范入库（**IT 目录批量** 或 知识库页 **Web 上传单套/小批量 ≤5 套**）；提供 **知识库网页** 与 **检索试用**；缺 Q&A/报价时 **可入库并提示**；历史报价解析为 **人天对照表** |
| **贵司需配合** | R1 验收：**3–5 套金标准三件套**（签约后 1 周内提供）；IT 完成 **服务器与内网环境**（最迟 R1 验收前）；全库 100+ 可 **R1 后分批**（目录批量 或 Web 补录） |
| **验收签字要点** | ① **入库成功**：**3–5 套金标准三件套**在知识库中可查到，无批量导入失败 ② **检索评测**：乙方提供 **≥15 条**预设检索问题及期望命中项目/文档；贵司工程师在检索实验室 **逐条试用**，**≥12 条**返回与期望相关的 Top 结果即为通过；**结果截图与《R1 检索评测记录表》一并存档、双方签字**（题集在第 4 周前基于脱敏样本共同确认，详见 [R1 验收说明](./R1-知识库验收与检索评测说明（客户版）.md)） ③ **人天对照表** 与源 Excel 可核对 |

**📌 里程碑付款：** 本项与下文 **2.2 一并验收**；全部通过后触发第一期付款（金额见 2.2）。

### 2.2 第一期 · RFQ 对标（R1，与上同期验收）

| 项目 | 内容 |
|------|------|
| **系统主要能力** | 上传 RFQ 后读出功能模块与交付物；找出 **3 个最相似历史 RFQ**；**先请您确认对比维度**，再生成 **可编辑的技术对比表** |
| **贵司需配合** | 提供有代表性的 RFQ；安排工程师参与 **解析是否准确**、**对比表是否合理** 的试用与调优（第一期 **第 7–8 周** 重点） |
| **验收签字要点** | **3 份 RFQ** 完整走通「上传 → 确认维度 → 生成对比表」并 **书面签字** |

**📌 里程碑付款：** **第一期 R1 验收通过后**（含 2.1 知识库与 2.2 RFQ 对标），对应里程碑付款 **¥76,300**。

### 2.3 第二期 · 人力报价 Excel（M3）

| 项目 | 内容 |
|------|------|
| **系统主要能力** | 自动选出与当前 RFQ **开发范围最相似** 的历史报价作参考；抽取各岗位人天；按 **当前 RFQ 的里程碑日期** 填入 Excel（**不是**整表复制旧项目日期）；附带 **填充说明** |
| **贵司需配合** | 签约时 **书面签收** 报价 Excel 模板；第二期验收前，对 **至少 3 个 RFQ** **书面确认**「系统选中的参考历史项目是否认可」 |
| **验收签字要点** | ① 各功能模块 Sheet 可下载 ② **项目信息中的日期 = 当前 RFQ**（非历史项目日期） ③ 填充说明可理解、缺口可追踪 ④ **人天数值合理性**由贵司工程师书面确认：系统提供参考初稿，工程师审阅修改后签字即为认可；**不以**人天与实际商务结论 100% 吻合为验收条件 |

**📌 里程碑付款：** 第二期 M3 验收通过后，对应里程碑付款 **¥30,500**。

### 2.4 第三期 · 澄清问题清单（M4）

| 项目 | 内容 |
|------|------|
| **系统主要能力** | 从相似历史项目的 Q&A 中 **按领域合并、去掉重复题**；按贵司模板导出；**不凭空编造新问题**；影响程度、历史依据等列按规则预填 |
| **贵司需配合** | 历史项目包中含 **标准 Q&A Excel** 样本；工程师试用导出文件 |
| **验收签字要点** | ① 导出格式与 **签收模板** 一致（8 列） ② 须工程师填写的列（如作者、答复等） **留空或留待填写** ③ **条数说明**：澄清问题来自相似历史 Q&A 合并去重，**不凭空造题**；若历史样本不足或某领域无先例，输出条数会相应减少，**最终条数以历史样本覆盖范围为准**，不承诺固定条数 ④ 试用样例认可 |

**📌 里程碑付款：** 第三期 M4 验收通过后，对应里程碑付款 **¥21,000**。

### 2.5 第四期 · 技术方案 PPT（M5）

| 项目 | 内容 |
|------|------|
| **系统主要能力** | 按贵司 **34 页 Content Template** 预填封面、里程碑、与本次范围相关的模块页；删除无关模块页；提供 **《哪些页已填/未填》说明报告** |
| **贵司需配合** | 签收 PPT 模板；第四期开始前 **书面确认**「RFQ 开发范围 ↔ PPT 哪些页」的对应关系 |
| **验收签字要点** | ① 预填 PPT 可打开、结构正确 ② **封面、里程碑、模块框架** 已按模板预填；**《哪些页已填/未填》说明报告** 列明每页状态并 **双方签字** ③ **技术正文**（Assumptions、Work Content 等）由贵司工程师 **负责审阅定稿**；系统预填内容仅作 **参考框架**，不作为对外终稿 |

**📌 里程碑付款：** 第四期 M5 验收通过后，对应里程碑付款 **¥36,200**。

### 2.6 上线 · 培训与移交（M6）

| 项目 | 内容 |
|------|------|
| **系统主要能力** | 五步报价流程 **全链路可用**；工程师与 IT **各培训 1 场**；提供部署/运维说明与备份脚本；组织 **一次备份恢复联合演练** |
| **贵司需配合** | **2–3 名工程师** 全流程试用约 **0.5–1 天**；IT 参与备份演练 |
| **验收签字要点** | ① 全链路试用通过 ② 培训完成 ③ 备份演练完成 **书面签字** |

**📌 里程碑付款：** 上线 M6 终验通过后 **¥13,800**；质保尾款 **¥5,200**（上线 3 个月内无 P0 严重缺陷后支付；合计 **¥19,000**）。

## 3. 各阶段为何特别需要贵司配合

> 说明 **哪些阶段更依赖贵司样本、确认与试用排期**；**不代表** 额外收费或增加人日。工期顺延规则见主方案 **第七章**。

| 阶段 | 效果是否因 RFQ/样本不同而有差异 | 贵司配合重要程度 | 说明（与验收相关） |
|------|--------------------------------|-----------------|-------------------|
| **第一期 R1** | **高** | **高** | 三件套样本、RFQ 解析与对标须工程师确认；真实数据调优约 **第 7–8 周** |
| **第二期 M3** | 中 | **高** | 须 **书面确认** 参考历史报价是否选对；Excel 日期须对应当前 RFQ |
| **第三期 M4** | **高** | **高** | 依赖历史 Q&A 质量；作者、答复等须工程师后续填写 |
| **第四期 M5** | 低 | 中 | 模板预填为主；技术正文 **工程师自写** |
| **上线 M6** | 低 | 中 | 组织试用与培训；**不含** 多轮大范围需求变更返工 |

**第二期需重点配合的原因：** 系统要在多份历史报价中选出与 **当前 RFQ 开发范围** 最相似的一份，并把人天与里程碑 **改排到当前 RFQ 的时间轴** — 高度依赖样本质量与您 **书面确认的参考项目**。

## 4. 贵司配合延误对进度的影响

下列情况可能导致 **日历顺延**（一般 **不自动增加** 合同软件开发费；范围变更除外）：

| 贵司配合项 | 影响的阶段 |
|-----------|-----------|
| 服务器 / 数据盘 / 内网环境 **未在第一期验收前就绪** | 第一期正式验收 |
| 历史项目包 **迟交**，或缺少 Q&A / 报价 Excel | 第一、二、三期 |
| RFQ **第四节开发范围** 格式与标准样本差异大 | 第一、二、四期 |
| 报价或 PPT **模板 / 页面对应关系** 未书面签收或确认 | 第二、四期 |
| 各阶段 **工程师试用** 排期空档 | 对应阶段验收签字 |

## 5. 人机分工（验收时请牢记）

| 分工 | 说明 |
|------|------|
| **系统 + 历史资料** | 约 **50%–70%** 可参考内容：解析、检索、合并、模板预填、人天初稿等 |
| **报价工程师** | 约 **30%–50%** 须审阅、修改、补充：**对比表、人天、Q&A 答复、PPT 技术正文** 等 |
| **验收标准** | 以 **本附录与各阶段签字表** 为准，不以「AI 主观满意度」单独作为拒付理由 |

各阶段 **哪些环节用 AI、哪些用历史数据规则**，详见主方案 **[客户易懂版 §1.4、§2](./ARIA-报价助手-正式版交付方案与报价（客户易懂版）.md)**。

## 6. 验收、付款与质保

| 项目 | 说明 |
|------|------|
| **分阶段验收** | 第一 / 二 / 三 / 四期 **各自签字** 后，对应里程碑付款（金额见主方案 **§六**） |

| **1 次体验优化** | 质保期内可提 **1 项** 合理小优化（见主方案 **§8.2**） |
