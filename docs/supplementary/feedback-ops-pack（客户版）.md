# 引用反馈运营包（客户版）

**版本：** v1.0 · 2026-07-02  
**关联：** [平台知识库演进路线](../平台知识库演进路线（客户版）.md) v1.1 · prod F5.6

> **定位：** 首期合同（¥18.3 万）**不含** 本包；若贵司希望上线后 **持续改进检索质量**，可选 L1 或 L1+L2。  
> **重要：** 本包 **不训练 / 不微调** 本地大模型；「变准」靠 **人标注 + 工程调优 + 索引/数据修正**。

---

## 1. 为什么需要（客户场景）

| 场景 | 无反馈产品时 | 有 L1/L2 后 |
|------|-------------|------------|
| 检索实验室某条结果不相关 | 口头或邮件告诉乙方 | 网页点 **「不相关」**，留记录 |
| RFQ 对标出现不应有的相似项目 | 手动改对比表 | 点 **「不应出现此项目」** + 可选填正确项目 |
| 乙方批量优化检索 | 难统计哪些 query 常错 | 导出反馈列表，季度复盘 |
| 客户期望「越用越准」 | 仅靠加文档 + 人工调优 | L2 固定 **审查 → 更新评测集 → 重跑索引** SOP |

---

## 2. 两档产品

### L1 · 反馈收集 MVP（推荐起步）

| 项 | 内容 |
|----|------|
| **含什么** | 知识库检索结果、RFQ 相似项目行 **「引用不准 / 不相关」**；可选备注与「应为某项目」；后台 **列表 + JSON/CSV 导出** |
| **不含什么** | 自动改检索权重；运营看板；LLM 微调；反馈条数作为里程碑付款条件 |
| **谁维护** | 贵司管理员导出；乙方 **hypercare / 年度运维** 中处理（频率另议） |
| **参考投入** | **5–8 人日** |
| **参考报价** | **¥15,000 – ¥25,000**（含税与否以正式报价单为准） |
| **建议时机** | **M6 上线后 1 个月内** 或写入 hypercare 附件 |

### L2 · 运营闭环（在 L1 之上）

| 项 | 内容 |
|----|------|
| **含什么** | L1 全部 + 管理员 **反馈审查页**；失败 query 汇总；**并入 R1 评测集** 流程；[ops-guide](../ops-guide.md) 月度 SOP 第 7 步可执行 |
| **不含什么** | Hybrid/Rerank（可另购技术升级包）；自动 overnight 变准 |
| **参考投入** | **12–18 人日**（含 L1） |
| **参考报价** | **¥35,000 – ¥50,000**（L1+L2 打包；以正式报价单为准） |
| **建议形态** | **变更单** 或 **年度平台运维** 首年赠送/折扣另议 |

### L3 · 检索技术升级（独立项）

Hybrid / Rerank / 反馈加权检索：**15–25+ 人日**，与 L1/L2 **分开报价**，见演进路线「技术升级包」。

---

## 3. 「大模型怎么知道错了？」（必对客户说明）

1. 工程师在网页点反馈 → 系统 **写入反馈库**（不修改 Qwen 权重）。  
2. 管理员/乙方 **定期审查** 导出记录。  
3. 采取 **工程动作**：修正项目包 metadata、补充评测题、重跑索引、（可选）上 Hybrid。  
4. **下次** 同类 query 检索更好 — 这是 **系统运维结果**，不是模型「记住了上次错误」。

---

## 4. 与首期验收的关系

- **R1 签字** 仍按 [R1 验收说明](../R1-知识库验收与检索评测说明（客户版）.md)（≥15 题 / ≥12 通过），**不依赖** L1 反馈按钮。  
- 采购 L1/L2 **不替代** 工程师审阅定稿；**不承诺** 100% 检索准确。

---

## 5. 采购建议（给 EDAG 业务 / IT）

| 贵司目标 | 建议 |
|---------|------|
| 首期只关心能用、能验收 | **不购** 本包；用 R1 评测表 + 人机分工即可 |
| 上线后希望「不对能点一下」 | **L1** |
| 希望季度复盘、可度量改进 | **L1 + L2** |
| 项目代号必须精确命中 | 加购 **Hybrid/Rerank 技术包**，与 L2 可并行 |
