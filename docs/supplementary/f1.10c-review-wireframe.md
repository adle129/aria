## 2. 复核视图（默认 Tab）

### 2.1 顶部 Alert

- **标题：** 基准维度确认（F1.10c）
- **说明：** 系统已自动处理大部分维度；请重点核对「待确认」项，展开含纳入项的模块后确认。

### 2.2 摘要条（Statistic / Alert）

```
┌─────────────────────────────────────────────────────────────────┐
│  共 100 项  │  自动纳入 18  │  待您确认 12  │  已排除 70        │
└─────────────────────────────────────────────────────────────────┘
```

数据来源：`dimension_draft.review_summary`（后端）或前端按 `review_tier` 聚合。

### 2.3 模块卡片行

每个 `module_summary` 一项，横向卡片或 Tag 增强版：

```
┌─ 底盘 ──────────────────────────────────────────────────────────┐
│  建议纳入 5 项 · 待确认 2 项 · 已展开 ✓                          │
│  [ 展开细看 ]  [ 本模块全选 ]  [ 本模块全不选 ]                   │
└─────────────────────────────────────────────────────────────────┘

┌─ 内外饰 ────────────────────────────────────────────────────────┐
│  系统判断：不需要介入                                            │
│  [ 确认无误 ]                                                    │
└─────────────────────────────────────────────────────────────────┘
```

| 操作 | 行为 |
|------|------|
| 展开细看 | 展开下方该模块 `needs_review` 表；标记 `module_reviewed=true` |
| 本模块全选/全不选 | 批量改 `in_scope`；**不**替代展开 |
| 确认无误 | 仅当模块无 `needs_review` 且无需纳入时可用 |

### 2.4 待确认明细表（仅 `review_tier=needs_review`）

| 列 | 宽度 | 内容 |
|----|------|------|
| 纳入 | 70 | Checkbox |
| 维度 | 160 | `name` |
| 工作内容 | flex | Input（in_scope 时） |
| RFQ 依据 | 220 | `source_ref` + 可点击 snippet → Drawer |
| 匹配方式 | 100 | Tag：`source_label`（橙=模块推断） |

## 3. 完整清单 Tab（审计）

- 全量 Collapse 按 module（~100 行）
- 列：纳入 | 维度 | 工作内容 | 匹配方式 | RFQ 出处 | 档位
- 默认折叠全部模块；供 PM/签字抽检
- 不做「仅待确认」过滤

---

## 4. 确认门禁与按钮状态

| 条件 | 提示 |
|------|------|
| `in_scope < 1` | 禁用确认；「至少勾选 1 项」 |
| 含 in_scope 模块未展开 | 「请先展开【底盘】模块过目」 |
| `needs_review` 未全部 ack | 「还有 N 项待确认未处理」 |
| 全部满足 | 主按钮可点：「确认以上例外，生成对比矩阵」 |

`item_acknowledged`：用户编辑任意字段、切换勾选、或点「确认此项」时置 true（前端 state，随 PUT 保存 optional）。

## 6. 与矩阵页衔接

确认后 → `confirm-dimensions` → 仅 `in_scope=true` 行进入 Top-3 矩阵；审计 Tab 数据不变，供事后追溯。
