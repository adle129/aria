## 1. 一句话定义

**R1 = 内网可用的「历史项目知识库 + RFQ 全维度技术对标」；客户 R1 签字后，工程师即可在贵司 GPU 服务器上用真实历史库上传 RFQ、确认 ~100 项维度、生成 Top-3 对比矩阵，无需等待 M3–M6。**

M3/M4/M5 是在 **同一知识库** 上增量打开 Excel 生成、Q&A 导出、PPT 预填——不是「第一次能用系统」。

## 2. 与旧叙事差异

| 旧隐含信息 | 问题 | 新共识 |

## 3. 两阶段数据路径（P1 / P2）

| 阶段 | 数据 | 环境 | R1 时间 | 负责 |
|------|------|------|---------|------|
| **P1 · 脱敏验证** | ≥5 套 **完整**金标准 + 10–20 套结构试点（**可缺件**） | 乙方开发 / **已脱敏**副本 | **第 1–5 周** | 客户业务 + 乙方 |
| **P2 · 内网生产入库** | **客户现有历史项目库**（原始资料 **不脱敏出网**） | **仅贵司内网** GPU + `${ARIA_DATA_ROOT}` | **第 2 周起 IT 准备；第 5–8 周 import** | 客户 IT + 乙方远程协助 |

**安全原则：**

- **原始** RFQ/报价/Q&A **不离开贵司内网**；乙方不要求拷贝全库至开发方环境。
- 开发期格式/算法验证 **仅用 P1 脱敏金标准**。
- **R1 bulk 签字验收在贵司内网演示**（第 7–8 周），不在外网/dev 环境对原始 bulk 签字。

## 4. 三层语料模型

| 层级 | 规模 | 验收深度 | 用途 |
|------|------|----------|------|
| **A · 金标准（Golden）** | **≥5 套** **完整**三件套（**脱敏**，P1） | **逐套**：失败=0；baselines 人工核对 | §4.1/§4.2 |
| **B · 对标语料库** | 内网库 **≥15** indexed RFQ（推荐） | Top-3 + 15 题评测 | 排序差异、日常检索 |
| **C · Bulk Corpus** | **清点表 N**（约 **数十至百级**，**不写死**） | 清点表范围内 **≥90%** 已落盘 engagement 成功索引；**银/铜可缺件** | 生产对标库 |

**8 周数据时间线：**

| 周 | 重点 |
|----|------|
| **1** | 脱敏金标准 ≥3；O-02b 结构试点；M0/内网目录规范 |
| **2–3** | 开发联调（**脱敏**）；manifest；内网目录 **结构就绪** |
| **4** | **O-02d 历史项目清点表**；15 题确认 |
| **5–6** | 金标准 ≥5；**内网开始 bulk 落盘**；F1.10 联调 |
| **7–8** | **内网** bulk re-index + 检索调优 + **R1-β 签字** |

## 5. R1 签字硬杠（内部）

| # | 项 | 标准 |
|---|-----|------|
| 1 | 金标准（P1） | **≥5 套** 完整三件套；失败=0 |
| 2 | baselines | ≥2 份 × ≥3 Function 与源 Excel 一致 |
| 3 | RFQ 对标 | **3 份** RFQ 走通 F1.10（**内网**演示） |
| 4 | 检索 | ≥15 题、≥12/15 Pass；内网 **≥15** indexed RFQ（推荐） |
| 5 | Bulk（P2） | [bulk-import-workload-assessment.md](bulk-import-workload-assessment.md) **档位 A**（清点表范围 ≥90%） |
| 6 | 明确不含 | M3 Excel、M4 Q&A、M5 PPT、Hybrid/Rerank、SSO/AD |
|| 7 | 访问控制 | 登录 + 两角色（工程师 / 资料库管理员）+ RFQ 任务隔离 |
