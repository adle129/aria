# KH06 · 第 3 轮

**日期：** 2026-07-10  
**核心目标：** 补齐上传限制的前端预检和可见说明。

## 第 2 轮结果

- 上传 API 已改为分块写入数据盘 `.staging/{request_id}`，不再整包读取。
- path-based 原子落盘已接入，所有返回路径都执行 staging 清理。
- 23 个定向 unit/API 测试通过，恶意 ZIP 返回 400 且不留下半成品。

## 本轮缺陷

- 前端仅说明“最多 5 个 ZIP”，未提示 100MB、单文件、解压总量和压缩比限制。
- 选择超限文件或 ZIP/散文件混传时，要等后端上传后才失败。

## 本轮最小目标

- 选择阶段预检 5 套、100MB 和 ZIP/散文件混传。
- UI 清晰展示服务端 ZIP 安全限制与失败后的操作建议。
- Vitest 覆盖前端预检，复核窄屏换行和非颜色表达。
