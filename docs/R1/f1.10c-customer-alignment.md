# F1.10c 例外驱动复核 — 客户对齐会议议程

**版本：** v1.0 · 2026-07-08  
**时长建议：** 30 分钟  
**参会：** 报价工程师（主用户）、PM、ARIA 产品/开发  
**关联：** [rfq-dimension-baseline-spec.md §6](../supplementary/rfq-dimension-baseline-spec.md) · [customer-feedback-baseline.md §1.1 Q8](../customer-feedback-baseline.md)

---

## 1. 会议目标

1. 确认 F1.10c **「全量必审」→「全量可查 + 例外必审」** 是否可接受  
2. 确认 **`module_scope` 推断项默认不勾选** 是否符合工程师习惯  
3. 将 **复核 KPI** 写入 R1-β 验收标准（可选签字）

---

## 2. 背景（5 分钟）

客户 Q8 要求：机器匹配 ~100 项基准 → 人工复核 → 再出 Top-3 矩阵。

**问题：** 若工程师需逐行扫 100 行，系统未减少工作量，仅更换载体。

**方案：** 双 Tab — **复核视图**（默认，仅待确认 ~15%）+ **审计视图**（全量 100 行，签字/抽检）。

---

## 3. 待确认决策（15 分钟）

### 决策 A — 复核范围

| 选项 | 说明 |
|------|------|
| **A1（推荐）** | 日常只审「待确认」项；全量在审计 Tab 可查、可导出 |
| A2 | 维持现版：100 行全表必过目 |

**推荐 A1 理由：** 与「减少工作量」目标一致；审计 Tab 满足签字追溯。

### 决策 B — 模块推断项（module_scope）

| 选项 | 说明 |
|------|------|
| **B1（推荐）** | RFQ 仅含「底盘在范围内」、无「前悬」等关键词时，**默认不勾选**，工程师确认后才纳入 |
| B2 | 模块在范围内则默认勾选，工程师取消 |

**推荐 B1 理由：** 避免弱依据项被误纳入矩阵。

### 决策 C — 模块批量操作（保守策略 · 已内部选定）

- 允许「本模块全选/全不选」  
- **不允许**跳过展开模块过目  
- 含纳入项的模块须展开一次方可确认  

请客户确认是否认可。

### 决策 D — R1-β 验收 KPI

| KPI | 建议值 | 是否写入签字验收 |
|-----|--------|------------------|
| 需逐条细看的行数 | ≤ 总数 15% | ☐ 是 ☐ 否 |
| 单份 RFQ 复核时长 | ≤ 5 分钟（熟练用户） | ☐ 是 ☐ 否 |
| 确认后矩阵因维度漏/错回退 | < 5% | ☐ 是 ☐ 否 |

---

## 4. 演示要点（5 分钟）

1. 上传 RFQ → 摘要条：「待您确认 12 项」  
2. 模块卡片 → 展开底盘 → 并排 RFQ 片段 vs 系统结论  
3. `module_scope` 行：橙色 Tag + 默认不勾选  
4. 审计 Tab → 全量 100 行  
5. 确认门禁：未展开模块 / 未 ack 待确认项 → 按钮禁用
