**版本：** v0.2 · 2026-07-23

## 1. 业务语义（客户约定）

| 颜色 | 含义 | 建议结构化取值 |
|------|------|----------------|
| 绿色 | 沿用 | `reuse` |
| 红色 | 新设计 | `new` |
| 黄色 | 需要更改 | `modify` |

每个色标框通常含：**零件名称**、**Teile-Nr.（零件号）**、可选 Material 等字段。

**目标产出（Spike 验证）：** 从 PPT/PDF 内嵌图页提取结构化清单，供工程师复核；**不**自动写入人天/报价。

## 2. 现状结论（启动 Spike 前已知）

| 项 | 现状 |
|----|------|
| RFQ 上传 | 仅 `.docx` / `.doc` 文本路径 |
| 当前 LLM | Ollama `qwen2.5:14b`（**纯文本**），`/api/generate` |
| OCR / 视觉 | **未实现**；产品文档明确 OCR 为范围外 |
| PPT | `python-pptx` 主要用于方案**导出**，非变更图解析 |
| PDF 抽图/渲染 | **未接入**生产解析管线 |

→ **当前系统不支持**本能力；需 Spike 验证技术路径后再估正式工期与报价。

## 3. Spike 目标与非目标

### 3.1 目标（DoD）

1. 证明能否从 **真实客户样本**（≥5 页红旅图，来自 PPT 或 PDF）稳定抽出：`name` / `part_number` / `status`  
2. 对比两条技术路线的 **字段级准确率、耗时、显存**，给出 Go / No-Go 与正式方案推荐  
3. 产出变更单依据：人日粗估、硬件前提、与现有 Ollama 队列的冲突说明  
4. 明确人工复核是否为强制环节（预期：**是**）

### 3.2 非目标（本 Spike 不做）

- 不进生产 API / 前端正式入口  
- 不改 R1 验收范围、不承诺准确率 SLA  
- 不对接 PLM/TC、不自动改 BOM  
- 不引入公有云 Vision API（保持本地私有化约束）  
- 不把结果直接当报价依据

## 4. 候选技术路线

| 路线 | 做法 | 优点 | 风险 |
|------|------|------|------|
| **A · 多模态 VL** | 页图 → Ollama `qwen2.5-vl`（或同级 VL）→ JSON | 端到端快、少规则 | 密标签漏检；VRAM 高；与 RFQ 抢 GPU |
| **B · 色块 + OCR + 文本 LLM** | OpenCV 分色框 → OCR → `qwen2.5:14b` 对齐 | 颜色可控、可解释 | 版式一变要改规则；德文/小号字 OCR |
| **C · 混合（推荐评估）** | 色块裁切 ROI → VL/OCR 只读小框 → 14B 汇总 | 准确率通常更好 | 工程量介于 A/B 之间 |

Spike **必须跑 A 与 B（或 C）对照**，禁止只凭单次 Demo 拍板。

---

## 5. 建议架构草图（正式实施时，非 Spike 代码范围）

```text
上传 PPT/PDF
  → DocumentMediaExtractor（抽图 / 整页高分辨率渲染）
  → ChangeMapPageFilter（是否红旅图页）
  → ChangeMapVisionService（A/B/C 选定路径）
  → 结构化 JSON + confidence
  → 人工复核 UI（强制）
  → 可选写入任务附件 / 导出 Excel
```

与现有 `RFQAnalysisService` **解耦**；新 job 类型（如 `change_map_extract`）；共用 PG worker + Ollama lease。

配置预留：`OLLAMA_VISION_MODEL`、页渲染 DPI、单页超时、最大页数。

## 7. 建议验收指标（Spike 内部，可与客户共议）

| 指标 | 建议门槛（草稿，Spike 前可改） |
|------|-------------------------------|
| 零件号（Teile-Nr.）精确匹配 | ≥ 85%（密标签页可单独降权报告） |
| 状态色（绿/红/黄）正确 | ≥ 90% |
| 零件名称可用（人工可认） | ≥ 80% |
| 单页端到端（含渲染） | 记录 P50/P95；不设硬 SLA |
| 误报「新设计」 | 重点统计；正式版须可人工改 |

未达门槛 → **No-Go 或缩小范围**（例如仅导出人工标注模板，不做自动识别）。

## 9. 排期原则

- **默认不排入 R1 剩余 Wave**；客户确认「要做 + 样本到位」后再开 `feat/` 分支或变更单。  
- 可与 R1-PERF / M3+ **并行评估**，但 **共享 GPU 时禁止**与生产验收抢同一时段重负载。  
- Spike 脚本放 `scripts/spike_change_map_*.py`；**不**默认合并进 `RFQAnalysisService`。
