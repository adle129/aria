Phase 1：核心服务开发（3-5天）
目标： 把最底层的基础能力跑通，后续四个业务模块都依赖这里。
优先级顺序
markdown
1. 数据库模型 + 迁移脚本      ← 其他所有功能的基础
2. 文档上传 + 文本提取         ← 所有模块的输入来源
3. Ollama 连接 + RAG 检索     ← 所有 AI 功能的基础
4. 知识库导入脚本              ← 没有历史数据，模块一三四都没意义

Phase 2：四个业务模块开发（2-3周）
原则： 每个模块独立开发，按以下顺序（依赖关系决定顺序）：
markdown
模块四（Excel）← 最核心刚需，优先验证可行性
    ↓
模块一（RFQ解析+比对）← 其他模块的输入
    ↓
模块二（QA清单）← 依赖模块一的检索结果
    ↓
模块三（PPT生成）← 相对独立，最后做
每个模块的标准开发顺序
vbnet
每个模块遵循同一套流程：
Step 1: 写 Service 层（纯业务逻辑，不含HTTP）
Step 2: 写对应的 unit_tests/test_xxx.py（边写边测）
Step 3: 写 API 路由层
Step 4: 写对应的 API_tests/test_xxx_api.py
Step 5: 写前端页面组件
Step 6: 联调前后端

每日开发节奏建议
yaml
每天开发时遵循以下顺序，避免写完所有代码再测试：
早上：
  明确今天要完成的 1-2 个功能点
开发时：
  写 Service → 立刻写 unit test → 跑通
  写 API 路由 → 立刻写 API test → 跑通
  写前端组件 → 手动联调
结束前：
  docker-compose up 确认整体还能跑
  git commit（每个功能点一个 commit，信息清晰）
  
Commit 信息规范：
  feat: 完成 RFQ 文档上传接口（含参数校验和格式验证）
  feat: 完成 Excel 报价生成 Service 层 + 单元测试
  fix: 修复 LLM 返回非法 JSON 时的崩溃问题
  test: 补全知识库搜索接口的异常路径测试
